# 지역정착 정책 데이터 설정

## 통합 갱신 명령

```powershell
npm.cmd run policies:refresh
```

목록 갱신 → 상세자료 보강(기본 최대 100건) → 지역 검토 대기목록 생성을 순서대로 실행합니다. 한 출처가 실패해도 다른 출처와 저장된 자료를 활용하고 최종 종료코드는 실패를 알립니다. 홈페이지 배포본은 갱신 후 다시 빌드·배포해야 반영됩니다. OS 자동 실행 작업은 등록하지 않았습니다.

목록·상세 수집기는 `data-source/policies.lock`으로 동시 쓰기를 막습니다. 비정상 종료 후 잠금 파일이 남으면 실행 중인 수집 프로세스가 없는지 확인한 뒤 그 파일만 제거하세요. 상세 캐시는 7일 또는 목록 버전 변경 시 만료됩니다. 오래된 지원대상으로 검증 상태를 유지하지 않도록 만료 자료를 숨기고 원문 확인 안내를 표시합니다. 상세 성공 20건마다 캐시를 임시파일에서 교체해 진행 상황을 보존합니다.

실패가 총 3건이 아니라 **연속 3건**일 때 중단하며, 인증/한도 오류는 즉시 중단합니다. 요청 간격은 250ms입니다. `data-source/policy-detail-status.json`에 안전한 실패 분류·정책 ID·남은 건수를 기록합니다. 응답 원문과 키는 기록하지 않습니다. 기본 실행 한도는 호출 시도 수 기준이며 실제 계정의 잔여 한도까지 보장하지 않습니다.

`npm.cmd run policies:audit`는 지역명이 지원대상에 명시된 후보, 코드표에 없는 제공 지역, 만료된 검토를 `data-source/policy-review-queue.json`에 모읍니다. 후보는 자동 승인하지 않습니다. 제외 조건·전입 예정·특정 세대 조건까지 원문을 대조한 후 기존 검토 기록 형식으로 추가하세요. 행정구역 연결표는 여전히 2025년 보유 자료 기준입니다.

## 지역 정확도 개선 (2026-10-28)

아래 기존 준비 안내보다 이 절의 구현 상태가 우선합니다. 상세 수집은 `npm.cmd run policies:details`로 실행합니다. 복지 API 상세의 지원대상·선정기준·지원내용·신청방법을 저장하며, 정부24는 목록 응답의 지원대상을 활용합니다. 기본 실행당 최대 100건이며 수집된 동일 버전은 캐시로 재사용합니다. 3건 실패 시 중단하고 성공 자료는 보존합니다. 이 API의 포털 안내 개발계정 한도는 1,000회이므로 실제 계정 한도와 잔여량을 확인하며 나누어 실행하세요. `POLICY_DETAIL_LIMIT`은 0~500으로 조절할 수 있고 0이면 네트워크 호출 없이 검토 기록만 적용합니다.

지역 상태는 `대상 지역 확인`, `제공 지역만 확인`, `지역 미확인`으로 구분합니다. 지도에는 제공 지역 정책도 포함되므로 상태를 표시하고, 원문 대조한 정책만 필터링할 수 있습니다. 제공 지역은 자격 보장이 아닙니다. 행정구역 코드는 보유 원자료의 2025년 기준이며 지원하지 않는 명칭을 추측해 연결하지 않습니다. 카드에서 코드와 근거를 펼쳐 볼 수 있습니다.

수정·검증 기록은 `data-source/policy-reviews.json` 배열에 추가합니다. 같은 정책 ID의 마지막 기록이 적용됩니다. `areas`에 시·도/시·군·구, `quote`에 지원대상의 정확한 발췌, `residence`에 거주/전입/출생등록 조건, `reason`에 수정 사유, `sourceUrl`, `reviewer`, `reviewedAt`, `fingerprint`를 기록합니다. 기존 기록을 삭제하지 않고 추가하여 이력을 유지하세요. `fingerprint`는 해당 정책의 `verification.fingerprint` 값입니다. 근거 발췌가 원문과 다르면 적용이 거부되며, 원문·수정시점·선정기준이 달라지면 검증이 만료됩니다. 이후 목록 재수집 시에도 상세 캐시와 유효한 검증 기록을 다시 적용합니다.

실제 원문 대조 결과와 남은 범위는 [지역정책 원문 대조 기록](policy-review-audit.md)을 참고하세요. 상세 수집 또는 코드 연결 자체를 전체 정책의 검증 완료로 보지 않습니다.

현재는 인증키 발급 전입니다. 샘플 정책은 제거했으며 실제 API 호출 성공을 확인한 상태는 아닙니다. 세 API의 목록 수집 어댑터와 검색 화면을 준비했습니다. 그린대로는 공개 정책 API를 확인하지 못해 공식 사이트 링크만 제공합니다.

## 1. 인증키 발급

공공데이터포털에 가입하고 아래 **두 서비스 각각** 활용신청을 진행하세요. 승인 상태와 요청 한도는 마이페이지에서 확인합니다.

- [행정안전부 대한민국 공공서비스(혜택) 정보](https://www.data.go.kr/data/15113968/openapi.do): `GOV24_SERVICE_KEY`
- [한국사회보장정보원 지자체복지서비스](https://www.data.go.kr/data/15108347/openapi.do): `WELFARE_SERVICE_KEY`

공공데이터포털 키는 일반 인증키 **Decoding** 값을 사용합니다. URL 인코딩은 수집 스크립트가 수행합니다. 같은 키를 사용하더라도 각 서비스의 활용승인이 필요합니다.

[온통청년 OPEN API 안내](https://www.youthcenter.go.kr/cmnFooter/openapiIntro/oaiDoc)에서 로그인 후 인증키를 신청합니다. 발급된 값을 `YOUTH_API_KEY`에 설정합니다. 실제 요청 매개변수 이름은 `apiKeyNm`입니다.

## 2. 로컬 설정 및 실행

Node.js 24 기준, 프로젝트 폴더의 PowerShell에서 실행합니다.

```powershell
Copy-Item .env.example .env.local
notepad .env.local
npm.cmd run policies:check
npm.cmd run policies:sync
npm.cmd run dev
```

이미 `.env.local`이 있다면 복사하여 덮어쓰지 말고 누락된 항목만 추가하세요. 따옴표 안에 실제 키를 넣어 저장할 수 있습니다.

```dotenv
GOV24_SERVICE_KEY="발급받은 Decoding 키"
WELFARE_SERVICE_KEY="발급받은 Decoding 키"
YOUTH_API_KEY="온통청년 인증키"
```

키를 채팅이나 Git에 올리지 마세요. `.env.local`은 Git 제외 대상이며 `VITE_` 접두사를 사용하지 않습니다. 브라우저는 API에 직접 요청하지 않고 수집된 JSON만 읽습니다. `policies:check`는 설정 유무만 확인하며 인증을 검증하지 않습니다.

## 3. 수집 동작과 범위

- 정부24: `/api/gov24/v3/serviceList` JSON 목록의 지원대상·내용·신청방법·기한·원문 URL을 저장합니다.
- 온통청년: `/go/ythip/getPlcy` JSON 목록을 수집합니다. 공개 안내에서 엔드포인트/요청인자는 확인했으나 상세 문서 조회는 인증이 필요했습니다. 현재 예상 응답은 `result.youthPolicyList`, `result.pagging.totCount`이며 **키 발급 후 첫 실응답 검증이 필요**합니다. 다른 형식이면 수집을 실패 처리하고 기존 자료를 유지합니다.
- 지자체 복지: `LcgvWelfarelist` XML 목록의 요약·신청방법·원문 링크를 저장합니다. 상세 자격은 링크에서 확인합니다. 사업 시행기간을 신청 마감일로 바꾸지 않습니다.
- 그린대로: [공식 홈페이지](https://www.greendaero.go.kr/) 안내만 제공합니다. API 수집 또는 정책 목록 통합이 완료된 상태가 아닙니다.

목록 전체 페이지를 수집하고 출처+원문 ID로 구분합니다. 출처 간 동일한 정책이 중복 표시될 수 있습니다. 데이터가 많으면 시간이 걸리고 요청 한도를 사용할 수 있습니다. 페이지 누락·중복·전체 건수 변동·인증 오류·시간초과는 해당 출처 전체를 실패 처리합니다. 자동 재시도 없이 기존 성공 자료를 유지하고 화면에 갱신 실패를 표시합니다. 로그에 인증키나 오류 응답 원문을 출력하지 않습니다.

정책의 지역은 보수적으로 처리합니다. 복지자료의 제공 시·도/시·군·구는 지역 검색에 사용하되 신청 자격을 보장하지 않습니다. 정부24 기관 소재지와 온통청년 지역 코드만으로 대상 주민을 추정하지 않으며 이 자료들은 현재 ‘지역 확인 필요’에서 조회합니다. **두 API의 자동 지역 연결은 추가 코드표/대상 지역 검증이 필요**합니다. 시·도 별칭과 일반구의 상위 시 정책을 지원하며 인구 지도에서는 최신 보유 연도(2025)의 행정구역 명칭을 사용합니다. 이후 행정구역 개편은 별도 갱신이 필요합니다.

분야는 제목/요약/지원내용의 키워드 분류입니다. 전체 공공서비스 중 정착과 무관한 정책도 ‘기타’에 포함됩니다. 신청기간은 원문 텍스트를 그대로 표시하며 모집 중 여부를 자동 확정하지 않습니다. 수집 결과는 과거 인구 연도별 정책 이력이 아닙니다.

## 4. 갱신·배포·점검

`npm.cmd run policies:sync` 실행 시 `src/data/policies.json`을 원자적으로 교체합니다. 키가 없는 출처는 이전 자료를 유지하며 미설정 상태로 표시합니다. 자동 갱신 스케줄은 설정하지 않았습니다. 필요할 때 다시 수집하고 `npm.cmd run build` 후 배포하면 갱신됩니다. 서버에서 예약 실행할 경우 키는 서버 환경변수/비밀 저장소에 설정하세요.

첫 실행 후 각 출처의 상태·건수·수집일을 확인하고 실제 정책 몇 건을 원문과 대조하세요. 실패 시 활용승인, Decoding 키, 요청 한도, 기관 장애와 응답 형식을 확인하세요. 현재 테스트는 모의 응답 기반이며 인증된 실데이터 수집 성공을 의미하지 않습니다.

```powershell
node --test tests/policy.test.mjs tests/population.test.mjs tests/long-term.test.mjs
node tests/render-population.mjs
npm.cmd run build
```
